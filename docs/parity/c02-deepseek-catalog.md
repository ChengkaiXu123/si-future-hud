## Summary (covered rows only)

Counts: same 10 · better 1 · deliberate 0 · missing 6 · differs 23 · unclear 3 (43 rows).

Top 10 most user-visible problems:
1. **DeepSeek liveness has no Harness process check.** A killed Harness keeps showing "running" for up to 30 minutes. A turn that has been quiet for over 30 minutes goes idle even though Harness is still alive (missing).
2. **Sub-agent sessions are shown and alerted.** DeepSeek sub-agent logs appear in the HUD session list and fire completion alerts. The snapshot has no sub-agent filter (differs).
3. **No tool-call activity for DeepSeek.** The shell, edit, read, agents and question states never show (missing).
4. **The balance "runs out" date uses a different method.** Next projects it from local cost per day. Open uses the balance readings since the last top-up. Top-ups and spending elsewhere are ignored (differs).
5. **Untitled sessions show their raw id.** The title reads "deepseek:<uuid>" instead of the folder name, also in completion alerts. Titles are 100 characters and can span several lines, instead of the 60-character first-line rule (differs).
6. **Notices and the Settings source list are English-only and worded as implementation notes.** **Fixed 2026-10-20:** notices are bilingual and the implementation notes are gone from the source list.
   - Source details read like "Client discovery only. Session and account readers have not been migrated…".
   - The DeepSeek 401 error tells the user to "sign in in its own client".
   - Qoder ×3 is listed as "detection-only" (differs).
7. **DeepSeek session cost is always "—".** Open shows an estimate in the account's currency for each session (missing).
8. **A failed balance read keeps the old balance on screen.** Open drops it. A missing key is also not reported as a failed read (differs).
9. **The topped-up and granted balance split is not shown** (missing).
10. **Format problems are silent.** An unsupported Harness log version, or a newer credentials document, fails with no notice or with a generic error. Open names the format problem, or reads the document through Harness's own parser (differs).

Two more cross-cutting gaps:
- **Short window names are missing.** `WindowNames.Period`, `distinct` and `shortLabel` have no counterpart in Next, so the panel cannot use the vendor-specific short names that Open uses in `QuotaCell`, `ModelUsageRow`, `AgentPeekView` and `OrderPane`. **Fixed 2026-10-20.**
- **There are no per-turn prompt marks**, so session usage is grouped per call rather than per turn.

## Architecture notes (from the Next code read)

- **Serial collection holds.** Account readings run on one worker thread, in a fixed reader order, under the shared `CollectionGate`, one at a time (`platform/src/accounts/mod.rs:96-112,490-505`). No parallel provider, account or log reads were seen in the code read.
- **Notices are English-only and live in Rust.** **Fixed 2026-10-20** (`l10n::text`).
  - Account and source notices are hard-coded English in Rust: `agents/src/deepseek/account.rs`, `agents/src/account.rs`, and the implementation-status notices at `core/src/lib.rs:711-723`.
  - They reach Settings and the panel unlocalized. Open keeps bilingual `L10n` strings in Core.
- **Business rules in UI/TS.** Settings ordering ("detected first") is decided in `SourcesSettings.tsx:16` rather than in Core.
- **Duplicated home resolution.** The DeepSeek home is resolved twice with different rules: `os::variable` trims and `agents/src/deepseek/account.rs::directory` does not.
- **OS-specific code.** The DeepSeek reader has no OS-specific code: the macOS-only `lsof`/`proc_pidinfo` process check was dropped rather than abstracted (see the liveness row).
